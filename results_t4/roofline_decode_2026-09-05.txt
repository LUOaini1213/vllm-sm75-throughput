解码阶段受什么限制 —— 对「权重带宽假说」的量化检验
Colab Tesla T4 (sm_75) · Qwen2.5-1.5B-Instruct · vLLM 0.28.0
max-model-len 2048 · gpu-memory-utilization 0.85 · 跑于 2026-09-05

================================================================
背景：这一轮是来给一个假说找证据的
================================================================
量化对照那轮，GPTQ-Int4 比 fp16 快约 1.9 倍，推翻了我「T4 无 Marlin 所以会更慢」的预测。
当时给的解释是「解码受权重读取带宽限制，INT4 权重小 4 倍所以更快」，
**并明确标注了那是假说、没有测量证据**。本轮补证据。

判据在跑之前写死（notebook 第 0 节）：
  实测/下界 的离散度 ≤ 1.6  → 三者贴同一条屋顶 → 假说成立
  fp16 贴屋顶而量化版明显偏离      → 假说不完整
  三者都远离屋顶                   → 假说推翻

================================================================
一、屋顶：实测可达显存带宽（不用标称的 320 GB/s）
================================================================
537 MB 缓冲区，三个微基准：
  copy   （读+写）   241.4 GB/s   标称的 75%
  read   （纯读）    275.9 GB/s   标称的 86%   ← 用这个当屋顶
  triad  （读2写1）  238.9 GB/s   标称的 75%

解码时读权重是纯读，所以用 read 那个数。

================================================================
二、结果
================================================================
权重字节取自 vLLM 日志 `Model loading took X GiB memory`（实际驻留，比文件大小准）。
理论下界 = 权重字节 / 275.9 GB/s ，即「batch=1 每生成一个 token 至少要把权重读一遍」。

  变体          权重GiB   理论下界   实测TPOT   实测/下界
  fp16           2.98    11.60ms    14.58ms      1.26
  AWQ            1.10     4.28ms     7.20ms      1.68
  GPTQ-Int4      1.10     4.28ms     7.25ms      1.69

  离散度（最大÷最小）= 1.35 ≤ 1.6

**按跑前写死的判据：假说成立。**
三个变体都在纯权重带宽下界的 1.26–1.69 倍之内。考虑到这条屋顶
**只算了权重、没算 KV cache 读写、激活、kernel 启动与采样**，
能贴到这个程度，说明 batch=1 解码确实由权重读取主导。

================================================================
三、比「成立」更有信息的一条：量化没有拿满理论收益
================================================================
  权重之比      2.98 / 1.10 = 2.71×
  实测 TPOT 之比 14.58 / 7.20 = 2.03×
  → 只吃到理论访存收益的 2.03 / 2.71 = **75%**

而且 fp16 离自己的屋顶更近（1.26×），量化版更远（1.68×）。
差出来的这部分，**方向指向反量化开销**：INT4 权重读进来要先还原成计算精度，
这一步是 fp16 不需要付的。

**这是从残差反推的解释，不是直接测量。** 要坐实得做 kernel 级剖析（ncu），本轮没做。
面试若被追问，要说清楚这一层是推断。

================================================================
四、第二个推论也对上了：带宽受限 → 算力受限的拐点
================================================================
 并发   fp16 TPOT   AWQ TPOT   AWQ吞吐/fp16   GPTQ吞吐/fp16
   1      14.58ms     7.20ms       1.99×          1.97×
   2      14.73ms     6.97ms       2.04×          2.09×
   4      15.12ms     7.23ms       1.89×          2.03×
   8      15.90ms     7.81ms       1.98×          1.86×
  16      17.55ms     9.76ms       1.68×          1.63×
  32      23.16ms    14.22ms       1.52×          1.50×

—— 并发 1→8，TPOT 几乎持平（14.58→15.90 / 7.20→7.81），量化优势稳定在约 2×：
   **权重读取被整个 batch 摊薄，仍是带宽主导。**
—— 并发 16 起 TPOT 明显抬头（17.55→23.16 / 9.76→14.22），优势收窄到 1.5×：
   **算力开始成为瓶颈，量化省访存的价值被稀释。**
—— **拐点在并发 8 与 16 之间**，这就是这块 T4 上「带宽受限 → 算力受限」的分界。

================================================================
五、可比性与边界
================================================================
1. 与量化那轮可比：同硬件、同模型、同参数。fp16 并发1 吞吐两轮分别 66.3 / 67.7 tok/s，
   TPOT 14.89 / 14.58 ms —— 轮次间差异约 2%，可视为同一条件下的复现。
2. **屋顶只计权重读取**，没算 KV cache 读写、激活张量、kernel 启动与调度。
   所以「实测/下界」天然 > 1；判据看的是**三者之间是否接近**，不是绝对值。
3. 带宽微基准是大块连续访问的**乐观上界**，权重读取有布局与 tile 的额外开销。
4. **这不是 nsight/ncu 的真实剖析**，是 roofline 量级检验。
   能证明「量级上受带宽主导」，不能定位到具体 kernel。
5. 单次测量、无重复跑。
6. AWQ 与 GPTQ 的权重占用日志都报 1.1 GiB（Checkpoint size 分别 1.5 / 1.07 GiB），
   两者理论下界相同，实测也几乎相同（7.20 / 7.25 ms）——**不宜宣称谁更快**。
