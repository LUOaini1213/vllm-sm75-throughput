Colab Tesla T4 (sm_75, 15360 MiB) · Qwen2.5-0.5B-Instruct · 并发 8 / 32 请求
共享前缀 2380 字符 · bench_serving.py SHA(前16) = ef5bf10717ecdacf（两边同一份）
跑于 2026-09-05

为什么有这一轮
--------------
此前 vLLM 只有「同一服务内有无共享前缀」的差（TTFT −35% / 吞吐 +2.3%），
而 SGLang 有「特性开 vs 关」的差（1.54× / −73.4%）。**两个口径不同，不能并列。**
本轮给 vLLM 补上关闭 --enable-prefix-caching 的那一组，两边才可比。

================================================================
vLLM 0.28.0（默认后端）
================================================================
                          吞吐 tok/s    TTFT p50
  --enable-prefix-caching 开
    无共享前缀                1225.9       48.3ms
    共享前缀 2380 字符        1016.8       65.5ms
  --no-enable-prefix-caching 关
    无共享前缀                1215.9       49.2ms
    共享前缀 2380 字符         861.9      169.2ms

  KV cache: 905,344 tokens, 2048 上下文理论并发 442.06×
  起服务耗时: 开 116s / 关 58s

================================================================
SGLang 0.5.19（Triton attention + PyTorch sampling，非默认最优路径）
================================================================
                          吞吐 tok/s    TTFT p50
  RadixAttention 开
    无共享前缀                1109.2      100.9ms
    共享前缀 2380 字符         832.7      123.6ms
  RadixAttention 关
    无共享前缀                1046.6       69.4ms
    共享前缀 2380 字符         540.3      464.9ms

================================================================
同口径结论：特性「开 ÷ 关」，共享前缀场景
================================================================
                  吞吐              TTFT p50
  vLLM      861.9 → 1016.8         169.2 → 65.5 ms
            = 1.18×                = 降 61.3%
  SGLang    540.3 →  832.7         464.9 → 123.6 ms
            = 1.54×                = 降 73.4%

—— 两个框架的前缀复用都有效，**SGLang 的相对收益更大**（1.54× vs 1.18×；
   TTFT 降 73.4% vs 61.3%）。
—— 但**关掉时的绝对表现 vLLM 明显更好**（861.9 vs 540.3 tok/s，169.2 vs 464.9 ms）。
   SGLang 收益比更大，部分原因是它关掉后的基线更差。
   **只报收益比会得出误导性结论，两组绝对值必须一起给。**

================================================================
无共享前缀场景：开着这个特性要不要付代价
================================================================
  vLLM      吞吐 1215.9 → 1225.9（1.01×）   TTFT 49.2 → 48.3 ms（几乎不变）
  SGLang    吞吐 1046.6 → 1109.2（1.06×）   TTFT 69.4 → 100.9 ms（**恶化 45%**）

—— **vLLM 的 prefix caching 在无复用场景下几乎不收费**（两项都在噪声量级）。
—— **SGLang 的 RadixAttention 则要付 TTFT 代价**（+45%）。
   这是本轮两个框架之间最清楚的一个差别。

================================================================
边界（一条都不许省）
================================================================
1. **SGLang 跑的不是默认最优路径**（Triton attention + PyTorch sampling，
   而非默认 flashinfer）。**纵向比两框架绝对值时必须带上这条**；
   横向比各自的「开 vs 关」不受此影响。
2. 单次测量、无重复跑、无置信区间。vLLM 这一轮没有出现离群值；
   SGLang 那一轮有两处（并发 16、稳态 3 条）未复现，本文件未引用它们。
3. 0.5B 模型 / 2048 上下文 / 单卡 T4 / 共享前缀仅 2380 字符。
   前缀越长、复用率越高，收益应越大；本结论不可外推到长前缀或生产规模。
4. vLLM 0.28 已把 `--disable-log-requests` 改名为 `--no-enable-log-requests`，
   照旧参数起服务会 argparse 退出码 2。本轮实测踩到并修正。
